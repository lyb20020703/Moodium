## 4. 当前产品流程与已确定的行为

### 4.1 开机、选关、设置

开机动画 → 语言／是否有感官袋选择 → 对应选关 → 进入糖果或自然世界。

- `Moodium.Language`：`Chinese` / `English`。
- `Moodium.HasSensoryBag`：1 / 0；缺省有袋，由 `SensoryBagOwnership` 管理。
- 有袋：扫描贴纸识别世界，沿用开机视频选关展示；点击进入后用默认校准数据直接确认，不强制走手动校准。
- 无袋：使用 CandyWorldUI／NatureWorldUI 轮播选关；进入后通过桌面查找与校准框定位。
- 选关已新增轻量设置面板：中文／English、有／无感官袋，当前选项带标记，修改保存后重建选关；不重播开机动画。
- 有袋界面原先存在一触即切到无袋的按钮，引起实机误触。已先移除并拦截旧回调；后来新增的设置面板才是当前正式修改入口。必须验证普通点击／移动窗口不会再改袋状态。
- 无袋流程必须持续关闭图像追踪，不能后续进入世界时意外重启；设置显式切回有袋除外。

### 4.2 校准

- 复用 `SensoryBagCalibrationCoordinator`、`SensoryBagCalibrator`、`CalibratedSensoryBagPresentation`，两条进入路径共享确认与展示。
- 默认数据源 `CreateInitialData` / `CreateDefault`；原分支设计约定宽 .40、高 .25、深 .05、中心零、支撑平面 Y 偏移 -.05。修改前再核对当前配置，不要在 AppFlow 写第二套变换。
- 无袋依赖现有 XROrigin／ARPlaneManager；只找水平桌面，超时使用视线前方后备锚点；用户操作框后不应再被迟到的平面强行搬走。
- 早期手动路径相对贴纸路径出现 Y 轴视觉翻转 180°，已修正桌面锚点反向朝向；长宽调整只改数值，不应交换模型方向。
- 最近加入左转／右转 5°，围绕框中心旋转，保持尺寸；确认后模型、圆形视频和手部引导应共同继承明确旋转。重置恢复初值。
- 左右按压引导手上下往复已从约 .36 秒放缓至约 1.8 秒。

### 4.3 世界交互与 Moodi

- 糖果／自然主体验由 `CandyWorldManager` 共用管理，勿因类名误认为仅管理糖果。
- 实体感官袋／数字 Soft 的按压积累能量，解救 Moodi，并驱动房间环境与阶段奖励。
- 自由、节奏、呼吸三种模式已有桌面 UI；用户曾反馈反复点击才响应，尚无本次真机验收结论。
- 教学改为桌面「?」按需打开，支持翻页和模式联动；不要恢复自动弹教学卡。
- 情绪检测是按需入口，不强制开场检测或退出后测。无袋确认心情直接完成，不显示贴纸推荐卡；有袋可显示推荐。推荐的“再选一次”按钮已移除。
- 手腕保留能量、礼物、Release、Exit；Exit 当前要求单击退出，旧双击确认方案已被取代；Release 仅满能量可用。
- 散步 Moodi 曾放大至约 20 cm、去掉光晕；房间糖纸增加 UI 视线保护。均需要与后续代码和实机行为一起回归。

### 4.4 糖果屋与悬浮进度

- 当前两个糖果屋和 Honey Jar 使用原始 Mesh；`CandyCompletionHouseController.SpawnHouse` 已移除 `PointCloudModel.TryAttach`。
- 当前出现节点：大糖果屋 55%、Honey Jar 75%、小糖果屋 90%；早期聊天的 80%／100% 已过时。
- 保留局部软体凹陷、多手指接触、松手回弹、音效、实际触点爆糖果。不要重新用根节点整体上下移动／缩放冒充局部形变。
- `CompletionHouseSoftInteraction` 使用独立实例网格；源 Mesh 必须开启 Read/Write。实际糖果屋网格约 26 万顶点，触碰性能需上机测。
- 新增 `FloatingSqueezeProgress`：绑定当前 Soft，在可见渲染 bounds 顶部上方 .065 m 显示约 .18 m 宽的细条，朝向用户、不接收点击；从同一个 normalizedProgress 更新，退出隐藏。

### 4.5 泡泡世界和嵌套世界

- 主旅程已有 Rescue → Explore → Bubble → Ending 的生命周期；满能量并不等于立即跳泡泡，应由旅程／光环入口控制。详见 finale 验证文档。
- 泡泡有微缩预览、触碰／注视捏合、飞近、包围、分层展开、房间返回／退出；进入时房间内容暂停隐藏，返回恢复。
- 自然第一层与糖果第一层都已提升至 500000 点，从真实源扫描增加采样，非简单复制原点。
- 每套完整点云为 20 层、每层 25000 粒子／100000 顶点、UInt32 索引、4096² 柔边颜色图。当前工程还包含两套第二层资源，共 80 个烘焙层网格。
- 渲染是 stock URP/Unlit + 柔边纹理四边形，并非参考仓库的完整 Metal 椭球协方差 Gaussian Splat 渲染器；不能对外声称已移植完整高斯渲染管线。
- 用户最新授权的微风仅作用自然／糖果泡泡世界，不扩展到外部房间树木或恢复网格的糖果屋。
- `BubbleWorldAmbientWind` 对每个粒子四角加同一个位置偏移，基于原始位置计算，避免累积漂移；约 15 Hz 更新，层起始时间错开；自然强度 .007、糖果 .004（扫描坐标米）。仅 Inside 启用，退出恢复源网格。另有原来的整层微漂移，两者目前叠加。
- 代码用 `m_Folder != NatureFolder` 判定糖果微风强度，因此 NestedNature 也会落到较弱强度。这是接手时应确认的语义细节，不能假定第二层自然已正确按主题区分。

## 7. 点云资产交接注意事项

1. 第一层资源位于 `MoodiumBubbleWorld/` 和 `MoodiumBubbleWorld/Candy/`；第二层由 `BubbleWorldData.NestedNatureFolder`／`NestedCandyFolder` 常量定义，勿凭目录名猜层级。
2. MSPC：20 字节头 + 每点 18 字节，50 万点应为 9000020 字节；坐标米制、近到远排序、eyeHeight 与实际点坐标要一致。
3. 第一层自然源 `cca18ee63731606db19fc8f5852b03f5 (1).ply` 有 1051081 条记录；糖果源 `4f1000ece08bf77f34813509d1de816f (1).ply` 有 711171 条记录。其余 PLY/SPZ/PNG 曾由用户通过 Downloads 提供。不要依赖微信缓存／`/tmp` 作为永久资产仓库。
4. 修改 points.bytes 后必须同步颜色 atlas、UV 顺序和所有烘焙 Mesh。单看点数不能证明颜色可见或坐标正确。
5. Python 图像行原点与 Unity atlas UV 原点不同；转换工具当前包含垂直翻转。不要误删 `pixels[::-1]`，应按实际 UV 检查每点 alpha。
6. 原脚本体素去重曾使指定 50 万实际只有约 41 万，导出后必须读实际头／记录数验收。
7. 真机包先烘焙；不要依赖 Editor 可以运行时生成网格就认定真机一定显示。
8. 微风依赖 Mesh readable；本次静态检查 80 个层网格均 `m_IsReadable: 1`。源资源不应被运行时直接改写。
9. panorama 提供的远景清晰度上限与点数分开；50 万点不自动提升背景分辨率。
