# 按钮交互排查：看着捏合（pinch）和手指直接点（poke）

基于 `8de6c1b` 的静态代码检查，没有上真机。

## 结论

**代码层面，几乎所有按钮两种方式都接受。** 所有 `MoodiumSpatialButton` 都由 `MoodiumSpatialInteractionController` 统一派发：只要收到系统空间指针的 Began 事件就按下，不区分是捏合还是触碰。唯一的类型判断只用于常春藤在空间网格上种植，和按钮无关。

PolySpatial 的输入碰撞层是 Default（`PolySpatialSettings.asset` 中 `m_ColliderSyncLayerMask = 1`），所有 UI 物体也都在 Default 层，层设置没有问题。

真正的问题有三类：

1. **一次触碰会按两下（严重，本包已修）。** `SensoryBagDirectTouchInput` 在指尖离按钮还有 12 mm、还没碰到时就按下，紧接着系统的触碰事件再按一次。
   - 校准的「升高 / 降低」每点一次会走两步（+10 mm）。
   - 普通 `MoodiumSpatialButton.Press()` 原本没有任何防连按。
2. **滑动 / 拖动可能弹回（中高，本包已修）。** 同一个辅助脚本会先抢占滑块、轮播、校准拖动的指针，之后系统触碰开始时，又被当作"第二个指针"拒收。两个脚本的执行先后不固定，所以这个问题时有时无。
3. **很多面板离得太远，手根本够不着（中等，需要你决定）。** 这些面板只能捏合，不能直接点。

## 本包已修

- `MoodiumSpatialButton.Press()`：加 0.3 秒防连按，同一次触碰两条输入路径都触发也只算一次。
- `SensoryBagCalibrationHandle`：确认、重置、升高、降低这几个一次性按钮同样加 0.3 秒防连按。
- `SensoryBagDirectTouchInput`：设为先于中央派发器执行（`DefaultExecutionOrder(-50)`）。系统触碰开始时，它先放开自己抢占的指针，派发器再接手，滑块和拖动不再弹回。

## 没修，需要你决定

- **远处面板要不要也能直接点？** 想两种方式都支持，可交互的面板要放在约 0.45–0.6 m。
  - 开场视频是 1.35 m 的"屏幕"，保持只能捏合比较合理。
  - 心情检测（0.75 m）、无感官袋轮播（0.7 m）、引导卡片（0.9 m）可以考虑拉近到 0.55–0.6 m，或在用户伸手时自动靠近。
- **开场视频输入只读第一个触点**：建议改成和中央派发器一样遍历所有触点，改动小。
- **传送门入口的 uGUI 语言按钮**：如果还在用，要加碰撞体；如果已废弃，可以删掉。
- **注视高亮**：很多精灵图按钮没有系统注视高亮，以前是因为高亮会照亮整个矩形贴图而有意去掉的。新悬浮按钮用了一个和玻璃同形的胶囊网格来承载高亮，如果真机效果好，可以推广到其他按钮。

## 无法静态确认的

- PolySpatial 2.4.3 在当前空间模式下，直接点是否真的会产生 Touch 事件。触发器碰撞体能否接收输入。很薄（2.4 mm）的碰撞体能否接住快速的点击。
- 不同人的手臂实际可及距离。
