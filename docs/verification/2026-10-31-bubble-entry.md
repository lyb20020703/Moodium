# 泡泡入口响应与加载优化

已确认输入漏点：Run 中泡泡已有可见飞入动画但仍为 Rising，Touch 以前仅处理 Floating/Portal。现在 Rising 的捏合/点击会记录请求，等飞入结束后进入，不会重复启动转场；新增 VisibleArrivingBubbleRemembersTheFirstPress 测试。

Build 原来对 warmupLayers 个核心网格连续同步 Resources.Load，核心层数可达十余层；改为核心和外围均 LoadAsync，每创建一个层后让出一帧。资源准备仍在世界会话开始时执行，不要求用户额外点击重试。此项平摊加载工作，尚未证明消除了 RealityKit 首次显示上传开销。

RoomContentVisibility 对 ImmediateHide 的糖果屋对象已同步停用，但动画循环仍给隐藏对象反复写缩放。现在隐藏期间跳过这些对象的视觉变换，保留快照和恢复行为。未改世界点数、点大小、材质或音频。

判断限制：糖果屋已有同帧隐藏处理，不能据此断言“糖果屋与泡泡同时点太多”就是主要根因。用户报告的真机卡顿仍需要设备性能数据确认；本次修复确定的点击状态缺口并减少已识别的同步工作，未宣称所有卡顿完全消除。RealityKit 的首显示、隐藏房间对象和喷射对象清理都仍可能贡献耗时。

Unity 6000.0.30f1 在独立副本最终全套 682 项：653 通过、29 旧失败，较 touch-growth 基线新增失败 0。新增点击回归通过，未改旧测试期望。[完整 XML](bubble-entry-1031/full-tests.xml)。代码已实施在原工程，本地提交，未推送。真机需复测糖果 100% 后第一次与重进时点击响应和帧耗时。
